# M2 GPU 학습 실행 가이드

> 대상: `re3draw-worker pose`로 카메라 위치가 나온 촬영본을 GPU에서 3D로 학습시켜
> `.ply` / `.spz` 스플랫을 얻는다.
> 작성일 2026-09-29 · 선행 문서 [m2-real-capture-test.md](m2-real-capture-test.md)

## 이게 무슨 단계인가

사진 여러 장과 각 사진의 카메라 위치를 넣으면, 공간에 수십만 개의 반투명한 타원체(가우시안)를
흩뿌려 놓고 **"이걸 그 카메라 위치에서 렌더링한 그림이 실제 사진과 같아지도록"** 파라미터를 수만 번
고쳐 나간다. 끝나면 사진에 없던 각도에서도 올바르게 보이는 3D 덩어리가 남는다.

미리 학습된 AI 모델을 쓰지 않는다. 물체 하나마다 매번 새로 계산하는 **최적화**다.

## 필요한 것

| 항목 | 요구 | 비고 |
| --- | --- | --- |
| GPU | NVIDIA, **VRAM 8GB 이상** | 물체 촬영은 실측 6GB 이하. 12~16GB 카드면 충분하고 4090은 과분하다 |
| 환경 | PyTorch + CUDA가 깔린 리눅스 | GPU 대여 서비스의 기본 템플릿을 그대로 쓴다 |
| 입력 | `pose` 결과가 있는 촬영 폴더 | `images/`와 `sparse/0/`이 들어 있어야 한다 |

Mac과 Windows에는 CUDA가 없어 **학습을 돌릴 수 없다.** `mat` / `pose` / `synth`는 그대로 쓸 수 있다.

## 1. GPU 빌리기

| 제공자 | RTX 4090 시간당 | 언제 |
| --- | --- | --- |
| [Vast.ai](https://vast.ai) | $0.29~0.39 | 개발·테스트. 최저가 |
| [RunPod](https://runpod.io) Community | $0.34~ | 개발·테스트 |
| RunPod Secure | $0.69~0.74 | 검증된 데이터센터. 실제 사용자 사진을 다룰 때 |

(2026년 9월 기준. 업계 중간값은 GPU당 시간 $0.42이고 하락 추세다.)

- **온디맨드로 빌린다.** 스팟(Vast 기준 $0.11)은 남이 더 비싸게 부르면 중간에 끊긴다.
  무인으로 학습만 돌릴 때는 괜찮지만, 디버깅 중에는 아낀 돈보다 시간 손해가 크다.
- 템플릿은 **PyTorch 2.x + CUDA 12.x**가 들어간 것을 고른다 (대부분 기본 제공).
- 디스크는 20GB면 넉넉하다.

> ⚠️ **실제 사용자가 올린 사진은 Vast.ai에 보내지 않는다.** 개인이 자기 그래픽카드를 빌려주는
> 장터라 호스트가 누구인지 보장되지 않는다. 개발용 테스트 사진만 쓰고, 운영은 정식 데이터센터로 간다.

## 2. 설치

파드에 접속해서 (대부분 웹 터미널 또는 SSH):

```bash
git clone <이 저장소> re3draw && cd re3draw
bash packages/worker/scripts/setup-gpu.sh
```

스크립트가 하는 일: GPU와 PyTorch 확인 → 설치된 torch 버전에 맞는 gsplat 미리 빌드된 휠 설치
(없으면 소스 빌드) → 워커 설치 → `.spz` 인코더 설치(선택) → **`pytest`로 자체 검증**.

마지막 `pytest`가 통과하면 합성 데이터로 짧은 학습까지 실제로 돌려본 것이다. 여기서 실패하면
사진을 올리기 전에 문제를 잡을 수 있다. 보통 2~5분 걸린다.

## 3. 사진 올리기

로컬에서:

```bash
rsync -avz --progress out/capture1/ root@<파드주소>:/workspace/capture1/
```

RunPod 웹 터미널만 쓴다면 제공되는 파일 업로드나 클라우드 스토리지(S3/R2)를 쓴다.
`images/`와 `sparse/0/`이 함께 올라가야 한다.

## 4. 학습 실행

```bash
re3draw-worker train /workspace/capture1 -o /workspace/capture1/splat
```

주요 옵션:

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--iters` | 30000 | 반복 횟수. 물체는 7000으로도 쓸만하고 그만큼 빨라진다 |
| `--max-size` | 1600 | 학습에 쓸 사진의 긴 변. 12MP 원본을 그대로 쓰면 느리고 이득이 적다 |
| `--cap` | 300000 | 가우시안 최대 개수. 줄이면 파일이 작아지고 빨라진다 (합성 12cm 물체: 10만/30만/100만 화질 동일) |
| `--sh-degree` | 3 | 보는 각도에 따른 색 변화(반사광)의 표현력. 0이면 각도와 무관한 단색 |
| `--object-width`, `--object-height` | 매트 기준 자동 | 물체를 가둘 상자 크기(미터). 물체가 작으면 줄이는 쪽이 품질에 좋다 |
| `--val-every` | 8 | 8장에 1장은 학습에서 빼고 채점용으로 쓴다. 0이면 전부 학습에 쓴다 |
| `--no-spz` | | `.ply`만 쓴다 |

## 5. 결과와 판정

`/workspace/capture1/splat/`:

- `splat.ply` — 모든 뷰어가 읽는 표준 형식
- `splat.spz` — 약 10배 작다. 폰으로 내려보낼 때 쓴다 (인코더가 설치된 경우)
- `train.json` — 아래 지표

| 항목 | 통과 기준 | 위치 |
| --- | --- | --- |
| 채점용 사진 화질 | **PSNR 25dB 이상**이면 양호, 20dB 미만이면 문제 | `psnr_val` |
| 학습/채점 차이 | 두 값 차이가 3dB 이내 | `psnr_train` vs `psnr_val` |
| 가우시안 수 | 5만~30만 (물체 오리기 사용 시) | `gaussians_exported` |
| 시간 | 4090 기준 30000회에 10분 내외 | `seconds` |

`psnr_val`이 `psnr_train`보다 많이 낮으면 사진이 부족하거나 각도가 치우친 것이다
(촬영 가이드의 중간·위 링을 확인한다).

## 6. 끝나면 결과를 내리고 **파드를 끈다**

```bash
rsync -avz root@<파드주소>:/workspace/capture1/splat/ ./out/capture1/splat/
```

그리고 콘솔에서 파드를 **종료(terminate)** 한다.

> 💰 이 프로젝트에서 돈이 새는 유일한 경로다. 물체 하나 학습은 70원 정도지만,
> 빈 파드를 한 달 켜두면 **약 39만 원**($0.39 × 24 × 30)이다. 계정에 지출 한도 알림을 걸어둔다.
> 디스크(볼륨)는 파드를 꺼도 과금되므로 쓰지 않을 볼륨은 삭제한다.

## 알려진 제한 (M2 기준)

- **배경이 섞여 들어온다.** 물체를 매트 기준 상자 안에 가두고 그 상자가 비치는 영역만 학습에
  쓰지만, 물체 옆으로 보이는 방 배경은 여전히 상자 안쪽에 떠다니는 조각으로 남을 수 있다.
  물체 분할(segmentation)을 붙이는 것이 다음 품질 개선 과제다.
- **`.glb` 메시는 아직 없다.** 스플랫에서 메시를 뽑는 것은 별도의 문제이고, 학습 방식 자체를
  바꾸거나 깊이 맵을 융합하는 단계가 필요하다. 뷰어는 `.ply` / `.spz`로 먼저 붙인다.
- **결과를 눈으로 볼 도구가 아직 없다.** M2 후반의 Three.js 뷰어가 그 역할이다.
  그전까지는 `splat.ply`를 기존 스플랫 뷰어에 넣어 확인한다.
- **사진 밑면은 복원되지 않는다.** 찍히지 않은 곳에는 정보가 없다.
