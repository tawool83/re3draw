# M2 실물 촬영 검증 가이드

> 대상: M1 카메라 위치 모듈(`re3draw-worker pose`)을 실제 폰 사진으로 검증하고,
> M2 3D 학습(gsplat)에 쓸 테스트 데이터셋을 확보한다.
> 작성일 2026-09-28 · 관련 커밋 `70a426c`

## 목표

1. 실제 폰 사진에서 카메라 위치가 합성 데이터만큼 정확하게 나오는지 확인한다.
2. 촬영 데이터를 M2 gsplat 학습 입력으로 재사용한다.
3. 매트 크기에 맞는 물체 크기, 촬영 가이드의 실제 난이도 등 문서 가정을 실측으로 확인한다.

## 1. 준비

### 매트 인쇄

```bash
cd packages/worker
.venv/Scripts/re3draw-worker mat --board a3 -o ../../out/mat_a3.pdf   # A4: --board a4
```

- 인쇄 설정은 **"실제 크기 / 100%"**로 한다. "페이지에 맞춤"은 끈다.
- 인쇄 후 자로 **100mm 눈금자가 정확히 100mm인지** 확인한다. 인쇄 배율 오차는 모델 크기 오차로 그대로 이어진다.
- 종이가 휘지 않게 책상에 테이프로 붙이거나 폼보드에 붙인다. 반사를 막기 위해 **무광 종이**를 쓴다.

### 매트 규격별 물체 크기 (M1 합성 테스트 결과)

| 매트 | 물체 최대 크기 | 촬영 거리 |
| --- | --- | --- |
| A4 | 폭 약 8cm, 높이 10cm | 약 40cm |
| A3 | 폭 약 20cm, 높이 18cm | 55~65cm |

물체가 매트 중앙을 가리기 때문에, 매트보다 물체가 너무 크면 검출되는 코너가 부족해진다
(예: A4 매트에 12cm 물체를 올리면 절반의 사진에서 실패).

### 테스트 물체 (2~3개)

| 용도 | 예시 | 확인할 것 |
| --- | --- | --- |
| 쉬운 경우 | 무늬가 있는 피규어, 인쇄된 상자, 운동화 (8~15cm) | 기준 품질 |
| 어려운 경우 | 무늬 없는 흰 머그컵 | 사진 경로의 약점 (추후 LiDAR 경로와 비교) |
| (선택) 작은 물체 | 5~8cm 물체를 A4 매트에 | A4 매트 검증 |

반사되거나 투명한 물체(유리, 크롬)는 범위 밖이므로 제외한다.

### 조명

흐린 날의 창가처럼 부드럽고 고르게 퍼지는 빛이 좋다. 플래시와 강한 그림자는 피한다.

## 2. 폰 설정 (중요)

현재 코드는 **모든 사진이 같은 렌즈, 같은 해상도**라고 가정하고 계산한다.

- [ ] **1x 메인 렌즈만** 사용하고 줌은 하지 않는다.
- [ ] iPhone: **매크로 자동 전환 끄기** (가까이 가면 초광각 렌즈로 바뀜)
- [ ] **HDR, 인물 모드, 라이브 포토 끄기**
- [ ] **폰 방향을 가로로 통일** (세로와 가로가 섞이면 섞인 쪽이 `image_size_mismatch`로 제외됨)
- [ ] iPhone: 사진 형식을 **"높은 호환성(JPEG)"**으로 설정 (현재 HEIC는 읽지 못함)
- [ ] 가능하면 초점과 노출 고정 (AE/AF 잠금)

## 3. 촬영 방법 (링 방식, 40~50장)

1. 매트는 **바닥이 아니라 책상이나 테이블 위**에 둔다. 바닥에 두면 서서 내려다보는 사진만 늘고,
   아래 링을 찍으려면 쪼그려 앉아야 한다.
2. 물체를 매트 **정중앙**에 놓고, 물체의 정면이 **FRONT 화살표 쪽**을 보게 둔다.
   - 물체 오리기(SAM 2)는 **"매트 중심 바로 위 = 물체"**라고 가정하고 그 점을 힌트로 쓴다.
     물체가 한쪽으로 치우치거나, 중심이 비어 있는 물체(도넛, 고리, 손잡이 사이로 중심이 뚫린 경우)는
     오리기가 실패한다. 실패한 사진은 자동으로 걸러져 물체 상자 기준으로만 학습되므로 멈추지는
     않지만, 배경이 섞여 품질이 떨어진다.
3. **물체와 매트는 절대 움직이지 않고, 사람이 주위를 돈다.**
   회전판을 쓰면 물체에 비치는 조명이 바뀌어 학습 품질이 떨어진다.
4. 첫 장은 FRONT 쪽에서 찍는다. 이 사진이 정면 방향과 썸네일 각도가 된다.
5. 매트가 최대한 많이 화면에 들어오게 찍는다. **매트가 인식되지 않은 사진은 카메라 위치를 몰라서
   학습에 쓸 수 없다.**

| 링 | 높이 | 장수 | 간격 |
| --- | --- | --- | --- |
| 아래 | 거의 눈높이 (10~15°) | 18장 | 약 20° |
| 중간 | 비스듬히 위 (30~45°) | 18장 | 약 20° |
| 위 | 거의 위에서 (60~75°) | 8~12장 | 약 30~45° |

- 흔들린 사진은 그 자리에서 다시 찍는다.
- **아래 링은 0°(완전히 옆)가 아니라 10~15°**다. 0°에서는 매트가 선처럼 보여 인식되지 않는다.
  폰을 테이블 높이에서 손가락 두세 개만큼 들어 올려 **살짝 내려다보고**, 물체만 꽉 채우지 말고
  **앞쪽 매트가 화면 아래쪽에 들어오게** 찍는다. 합성 테스트 기준 이 각도에서 18장 중 17장이 인식됐다.
- **중간 링과 위 링은 필수**다. 아래 링만으로는 렌즈 주점과 카메라 기울기를 구분할 수 없어서,
  재투영 오차는 작아 보여도 카메라 높이가 수 cm 틀어진다. 이 경우 `calibration_unstable` 오류로 막힌다.

## 4. 실행

사진은 `out/<촬영명>/images/`에 넣는다. `out/`은 `.gitignore`에 포함되어 커밋되지 않는다.

```bash
cd packages/worker
.venv/Scripts/re3draw-worker pose ../../out/capture1/images --board a3 -o ../../out/capture1/sparse/0
```

결과물 (`out/capture1/sparse/0/`):

- `cameras.txt`, `images.txt`, `points3D.txt`: COLMAP 형식 (M2 gsplat 입력)
- `poses.json`: 요약 (재투영 오차, 카메라 위치, 제외된 사진과 사유)

## 5. 판정 기준

| 항목 | 통과 기준 | 확인 위치 |
| --- | --- | --- |
| 위치 계산 성공률 | 전체 사진의 90% 이상, 링별 80% 이상 | `poses.json` → `views`, `rejected` |
| 재투영 오차 | 12MP 기준 약 2px 이하 | `poses.json` → `rms_reprojection_px` |
| 제외 사유 | 설명 가능할 것 (아래 링 1~2장의 `marker_not_found`는 정상) | `poses.json` → `rejected` |
| 정면 방향 | 첫 사진의 카메라 위치가 −Y 쪽 (`center[1] < 0`) | `poses.json` → `views[0].center` |
| 처리 시간 | 사진 50장 기준 1분 이내 | 명령 출력의 `seconds` |

### 오류 코드

| 코드 | 의미 | 조치 |
| --- | --- | --- |
| `too_few_views` | 매트가 검출된 사진이 8장 미만 | 매트가 더 많이 보이게 다시 촬영 |
| `calibration_unstable` | 고도 30° 이상 사진이 3장 미만 | 중간·위 링 추가 촬영 |
| `marker_not_found` (사진별) | 해당 사진에서 매트 코너 8개 미만 | 소수면 정상, 많으면 거리나 물체 크기 조정 |
| `image_size_mismatch` (사진별) | 다른 해상도나 방향의 사진 | 폰 방향과 렌즈 통일 |
| `reprojection_error_*` (사진별) | 오차가 큰 사진 (흔들림, 매트 휨) | 흔들림 확인, 매트 평평하게 고정 |

## 6. 추가 테스트 (선택)

| 테스트 | 방법 | 기대 결과 |
| --- | --- | --- |
| 불안정 캘리브레이션 방어 | 아래 링 사진만 따로 폴더에 넣어 실행 | `calibration_unstable` |
| 인쇄 배율 영향 | 일부러 "페이지에 맞춤"으로 인쇄한 매트로 촬영 | 위치는 계산되지만 크기가 틀림 (학습 후 치수로 확인) |
| 촬영 장수 민감도 | 링별로 장수를 절반으로 줄여 실행 | 성공률과 오차 변화 기록 |

## 7. 결과 기록과 공유

촬영마다 아래 내용을 남긴다.

```text
촬영명: capture1
기기 / 렌즈: (예: iPhone 15 Pro, 1x 메인)
매트: A3 · 눈금자 확인 결과 100mm = ___mm
물체: (이름, 대략 크기, 재질)
조명: (예: 흐린 날 창가)
사진 수: 아래 __ / 중간 __ / 위 __
결과: views __/__, rms ___px, 처리 시간 ___s
제외 사유 요약:
특이사항:
```

폴더 경로를 공유하면 `poses.json`을 분석하고, 통과하면 M2 gsplat 학습 워커와 Three.js 뷰어로 넘어간다.

## 알려진 제한 (M1 기준)

- HEIC를 읽지 못함 → JPEG로 촬영하거나 변환
- 세로와 가로 사진을 섞을 수 없음 → 폰 방향 통일
- 렌즈와 줌을 섞을 수 없음 (카메라 모델을 하나만 추정) → 1x 고정
- 결과를 눈으로 확인하는 도구가 아직 없음 → `re3draw-worker inspect` 추가 예정
  (사진마다 매트 좌표축 오버레이, 카메라 위치를 위에서 본 그림)
